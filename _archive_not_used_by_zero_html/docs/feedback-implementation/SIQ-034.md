# SIQ-034 — Consolidate Item Detail into one page

## Ticket

- ID: SIQ-034
- Comment: Consolidate Item Detail into one page
- Scope: Specific Screen
- Screen / Product Area: Item Detail
- Size: Large
- Workstream: Closet & Photo Import
- Original Description: Keep the hero image, primary styling action, core metadata, wear insights, cost per wear, compatibility, and item actions together with progressive disclosure.

## Problem

The current `0.html` prototype exposes this area through C-02–C-07 item detail subroutes. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-034.

## UX Decision

- Merge Image Tools, Core Metadata, Styling Metadata, Intelligence, and styling actions into one canonical item page.
- Put hero image and Style This Item first.
- Show essential metadata inline and insights contextually.
- Move edit/detail controls into expandable sections or sheets.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`C-01 → C-02 → separate C-03/C-04/C-05/C-06/C-07 screens.`

## Target Flow

`Current context → Consolidate Item Detail into one page → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens

- Audit/change: C-02–C-07 item detail subroutes
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
- New standalone route: not assumed; first attempt to solve inside the mapped canonical surface.
