# SIQ-053 — Keep a no-personal-photo option

## Ticket

- ID: SIQ-053
- Comment: Keep a no-personal-photo option
- Scope: Specific Screen
- Screen / Product Area: Style Twin
- Size: Medium
- Workstream: Style Twin
- Original Description: Allow users to create or use Style Twin without uploading personal face/body photos, while keeping full styling functionality available.

## Problem

The current `0.html` prototype exposes this area through H-01 entry, H-05 measurements/manual path, L-09 settings. The relevant rendering/routing surface is `screens registry, renderScreen, go, avatarScreen / mirrorTwinIntro / mirrorUpload, profileScreen / mirrorProfile`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-053.

## UX Decision

- Provide an explicit path to create/use Style Twin without face/body photos.
- Use measurements/appearance/manual avatar controls as the alternative.
- Do not block Try On-related exploration or the rest of StyleIQ when the user declines photos.
- Explain privacy and tradeoffs without pressuring the user.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`A-07/A-08 or H-01 → H-02–H-09 setup → H-10 result.`

## Target Flow

`Current context → Keep a no-personal-photo option → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
