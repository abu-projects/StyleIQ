# SIQ-058 — Add Weekly Style Recap

## Ticket

- ID: SIQ-058
- Comment: Add Weekly Style Recap
- Scope: Specific Screen
- Screen / Product Area: Weekly Style Recap
- Size: Large
- Workstream: Weekly Recap & Analytics
- Original Description: Create a useful weekly recap similar in spirit to an ongoing Wrapped experience, summarizing the user's real wardrobe behavior.

## Problem

The current `0.html` prototype exposes this area through NEW recap entry from D-02 Today and/or L-01 Profile; Planner handoff I-01. The relevant rendering/routing surface is `screens registry, renderScreen, go, homeScreen / mirrorToday / outfitFamilies, profileScreen / mirrorProfile, plannerScreen / mirrorPlanner`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-058.

## UX Decision

- Create a weekly recap experience designed for habit and usefulness rather than passive analytics.
- Use real tracked prototype state where available and clearly simulated sample data otherwise.
- Make the recap strongly visual with outfits/items.
- Give it a clear next-week handoff.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`No dedicated recap route exists; behavior is fragmented across I-02, L-01, and M-03.`

## Target Flow

`Current context → Add Weekly Style Recap → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
