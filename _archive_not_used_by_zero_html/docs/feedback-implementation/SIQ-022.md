# SIQ-022 — Use bottom sheets instead of unnecessary pages

## Ticket

- ID: SIQ-022
- Comment: Use bottom sheets instead of unnecessary pages
- Scope: General
- Screen / Product Area: Whole Product
- Size: Foundation
- Workstream: Product Simplification Foundation
- Original Description: Convert lightweight actions and choices such as feedback, item actions, planning options, visibility, and quick configuration into sheets instead of full screens.

## Problem

The current `0.html` prototype exposes this area through E-03/E-04 action routes, G-06 visibility, C-02 quick actions, I/J lightweight choices. The relevant rendering/routing surface is `screens registry, renderScreen, go, actionScreen, savedScreen, closetScreen / mirrorCloset`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-022.

## UX Decision

- Create/reuse one consistent bottom-sheet pattern.
- Convert lightweight actions such as quick feedback, item lifecycle actions, add-to-planner, filters, visibility, and source selection into sheets where appropriate.
- Preserve deep-linkable full screens only for real standalone jobs.
- Ensure sheets support dismiss, back, focus, and mobile safe-area behavior.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`The screen index exposes the capability through feature-specific routes, often with separate full-screen configuration, processing, and result states.`

## Target Flow

`Current context → Use bottom sheets instead of unnecessary pages → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens

- Audit/change: E-03/E-04 action routes, G-06 visibility, C-02 quick actions, I/J lightweight choices
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
- New standalone route: not assumed; first attempt to solve inside the mapped canonical surface.

## Technical Impact

- HTML/CSS/JS baseline: `0.html`
- Functions/routes: `screens registry, renderScreen, go, actionScreen, savedScreen, closetScreen / mirrorCloset`
- Shared UI: `shell`, root/bottom navigation, reusable sheet/overlay patterns, image components, and accessibility labels.
- State: reuse the relevant canonical prototype state; do not fork Closet, Look, Canvas, Planner, Trip, Twin, Lens, or Muse data.
- Persistence: the baseline has no canonical localStorage model; add persistence only when this ticket explicitly requires it and test migration/reset behavior.
- Tests: add/extend dedicated Playwright coverage for `0.html` on desktop and 375×812 mobile.
