# SIQ-029 — Design Closet to scale from 0 to 100+ items

## Ticket

- ID: SIQ-029
- Comment: Design Closet to scale from 0 to 100+ items
- Scope: Specific Screen
- Screen / Product Area: Closet
- Size: Large
- Workstream: Closet & Photo Import
- Original Description: Define clear visual states for an empty Closet, one item, a small wardrobe, and a large wardrobe with search, classification, and scalable browsing.

## Problem

The current `0.html` prototype exposes this area through C-01 Closet across 0/1/10/100+ states. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-029.

## UX Decision

- Design and implement distinct but coherent states for 0, 1, small, and large Closets.
- Ensure search, category navigation, smart collections, and sorting remain usable at high item counts.
- Do not let empty-state promotional content dominate once items exist.
- Test the layout with representative item counts rather than one hard-coded example.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`C-01 → C-02 → separate C-03/C-04/C-05/C-06/C-07 screens.`

## Target Flow

`Current context → Design Closet to scale from 0 to 100+ items → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
