# SIQ-023 — Use inline editing instead of separate forms

## Ticket

- ID: SIQ-023
- Comment: Use inline editing instead of separate forms
- Scope: General
- Screen / Product Area: Whole Product
- Size: Foundation
- Workstream: Product Simplification Foundation
- Original Description: Allow users to edit information in context or through lightweight sheets instead of navigating to dedicated edit screens for each data group.

## Problem

The current `0.html` prototype exposes this area through C-02–C-05 item edits, L-02 profile edit, G-02–G-06 look details, I-04 event edit. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset, profileScreen / mirrorProfile, savedScreen, plannerScreen / mirrorPlanner`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-023.

## UX Decision

- Identify edit-only screens that simply repeat information from the parent detail page.
- Move simple edits inline or into a contextual sheet.
- Keep advanced/long-form editing behind progressive disclosure.
- Do not duplicate the same data form in multiple places.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`The screen index exposes the capability through feature-specific routes, often with separate full-screen configuration, processing, and result states.`

## Target Flow

`Current context → Use inline editing instead of separate forms → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

- Audit/change: C-02–C-05 item edits, L-02 profile edit, G-02–G-06 look details, I-04 event edit
