# SIQ-012 — Lens: Shop my Closet from a screenshot

## Ticket

- ID: SIQ-012
- Comment: Lens: Shop my Closet from a screenshot
- Scope: General
- Screen / Product Area: StyleIQ Lens
- Size: Medium
- Workstream: StyleIQ Lens & Visual Search
- Original Description: Use screenshots or inspiration images to find similar pieces the user already owns before suggesting purchases.

## Problem

The current `0.html` prototype exposes this area through Lens screenshot result → C-01 matches → F-01 Make It Mine. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset, studioScreen / mirrorStudioV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-012.

## UX Decision

- Accept a screenshot or inspiration image.
- Extract the outfit/product visual formula and search the user's Closet for similar pieces.
- Prioritize 'you already own this/similar' before shopping suggestions.
- Offer Make It Mine / View Closet Matches as the primary result.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`Visual jobs are split between B import, C Closet, K Discover, M Muse, and J Trips; no canonical Lens route exists.`

## Target Flow

`Current context → Lens: Shop my Closet from a screenshot → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
