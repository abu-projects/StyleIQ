# SIQ-002 — Make the experience more image-first

## Ticket

- ID: SIQ-002
- Comment: Make the experience more image-first
- Scope: General
- Screen / Product Area: Whole Product
- Size: Foundation
- Workstream: Product Simplification Foundation
- Original Description: Increase focus on outfit imagery, garment photos, visual references, screenshots, camera inputs, and visual comparisons while reducing explanatory text.

## Problem

The current `0.html` prototype exposes this area through D-02 Today, C-01 Closet, K-01 Discover, L-01 Profile, H-01 Style Twin, F-01 Studio, plus A-13–A-15 empty states. The relevant rendering/routing surface is `screens registry, renderScreen, go, homeScreen / mirrorToday / outfitFamilies, closetScreen / mirrorCloset, discoverScreen / mirrorDiscover, profileScreen / mirrorProfile, avatarScreen / mirrorTwinIntro / mirrorUpload, studioScreen / mirrorStudioV2, onboarding`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-002.

## UX Decision

- Audit screens where text, cards, metrics, or forms dominate despite the task being visual.
- Promote outfit images, garment photos, before/after comparison, visual selection, screenshots, and camera entry points.
- Reduce supporting copy to what is necessary to explain a decision or action.
- Do not add decorative imagery that has no product meaning.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`The screen index exposes the capability through feature-specific routes, often with separate full-screen configuration, processing, and result states.`

## Target Flow

`Current context → Make the experience more image-first → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens

- Audit/change: D-02 Today, C-01 Closet, K-01 Discover, L-01 Profile, H-01 Style Twin, F-01 Studio, plus A-13–A-15 empty states
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
