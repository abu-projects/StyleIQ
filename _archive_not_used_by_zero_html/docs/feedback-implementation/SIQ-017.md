# SIQ-017 — Defer brand selection

## Ticket

- ID: SIQ-017
- Comment: Defer brand selection
- Scope: Specific Screen
- Screen / Product Area: Onboarding
- Size: Medium
- Workstream: Onboarding
- Original Description: Do not require users to select favorite brands before receiving value. Brand preferences can be learned from Closet items, receipts, likes, inspiration, and later profile editing.

## Problem

The current `0.html` prototype exposes this area through A-10 Brand selection, L-06 Brands. The relevant rendering/routing surface is `screens registry, renderScreen, go, onboarding, profileScreen / mirrorProfile`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-017.

## UX Decision

- Remove favorite-brand selection as a blocking onboarding requirement.
- Preserve brand preferences as an optional Profile/Style Intelligence feature.
- Allow StyleIQ to learn brands from imported purchases, Closet items, likes, creators, and shopping behavior.
- Do not delete the underlying preference capability.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`S-00 → S-01 → S-02 → A-series setup screens → A-11/D-02 first value.`

## Target Flow

`Current context → Defer brand selection → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

- Audit/change: A-10 Brand selection, L-06 Brands
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
