# SIQ-048 — Make Style Studio simple by default

## Ticket

- ID: SIQ-048
- Comment: Make Style Studio simple by default
- Scope: Specific Screen
- Screen / Product Area: Style Studio
- Size: Large
- Workstream: Style Studio
- Original Description: Default Studio should focus on understandable actions such as swap top, swap bottoms, swap shoes, add layer, add accessory, and Muse suggestions.

## Problem

The current `0.html` prototype exposes this area through F-01–F-11 with F-01 as simple default. The relevant rendering/routing surface is `screens registry, renderScreen, go, studioScreen / mirrorStudioV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-048.

## UX Decision

- Create a simple default editing mode focused on wardrobe language: swap top, bottoms, shoes, add layer/accessory, ask Muse.
- Do not expose design-tool architecture by default.
- Keep the visual preview central and image-led.
- Use Muse-suggested alternatives and owned items first.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`F-01 → technical layer/category/manual-selection screens → save.`

## Target Flow

`Current context → Make Style Studio simple by default → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens
