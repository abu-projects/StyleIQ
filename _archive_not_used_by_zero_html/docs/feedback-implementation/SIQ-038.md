# SIQ-038 — Support batch photo import

## Ticket

- ID: SIQ-038
- Comment: Support batch photo import
- Scope: Specific Screen
- Screen / Product Area: Closet Import
- Size: Large
- Workstream: Closet & Photo Import
- Original Description: Allow multiple photos to be processed together and present only unresolved or uncertain items for review.

## Problem

The current `0.html` prototype exposes this area through B-01/B-02/B-10/B-11 and C-01. The relevant rendering/routing surface is `screens registry, renderScreen, go, importScreen / mirrorItemUpload, closetScreen / mirrorCloset`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-038.

## UX Decision

- Allow multi-image import from the global Add/Lens flow.
- Process images as a batch and show aggregate progress rather than one full flow per image.
- Resolve duplicates and uncertain items in a batch review.
- Commit multiple Closet items safely and surface success as a lightweight summary.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
