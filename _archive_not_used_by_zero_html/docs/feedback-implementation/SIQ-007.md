# SIQ-007 — Lens: Add items from a Closet

## Ticket

- ID: SIQ-007
- Comment: Lens: Add items from a Closet
- Scope: General
- Screen / Product Area: StyleIQ Lens
- Size: Medium
- Workstream: StyleIQ Lens & Visual Search
- Original Description: Point StyleIQ Lens at clothing or a wardrobe and use the visual input to identify and add Closet items.

## Problem

The current `0.html` prototype exposes this area through Lens state → B-02/B-10 batch import → C-01. The relevant rendering/routing surface is `screens registry, renderScreen, go, importScreen / mirrorItemUpload, closetScreen / mirrorCloset`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-007.

## UX Decision

- From Lens, support pointing at a garment/wardrobe and starting Closet ingestion.
- Reuse the canonical Closet import pipeline rather than creating a Lens-specific item model.
- For multiple detected items, hand off to batch review rather than one-by-one screens.
- Return to Closet with visible added results.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`Visual jobs are split between B import, C Closet, K Discover, M Muse, and J Trips; no canonical Lens route exists.`

## Target Flow

`Current context → Lens: Add items from a Closet → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
