# SIQ-057 — Support natural-language Trip planning

## Ticket

- ID: SIQ-057
- Comment: Support natural-language Trip planning
- Scope: Specific Screen
- Screen / Product Area: Trips
- Size: Large
- Workstream: Trips
- Original Description: Allow users to describe the trip in one sentence including destination, dates, luggage, and activities, then generate the initial packing plan and outfits.

## Problem

The current `0.html` prototype exposes this area through J-01/J-02/J-06/J-07 canonical Trip context generation. The relevant rendering/routing surface is `screens registry, renderScreen, go, tripScreenV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-057.

## UX Decision

- Add a natural-language Trip input capable of describing destination, dates, luggage, and activities.
- Use a compact interpretation/review step only when necessary.
- Feed the interpreted context into the same canonical Trip generation model.
- Do not maintain a separate natural-language Trip implementation.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`J-01 → J-02 → J-04/J-05/J-06 → J-07 → J-08/J-09/J-10 → J-13 → J-14.`

## Target Flow

`Current context → Support natural-language Trip planning → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
