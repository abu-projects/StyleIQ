# SIQ-044 — Track Look creation source

## Ticket

- ID: SIQ-044
- Comment: Track Look creation source
- Scope: General
- Screen / Product Area: Looks / Data
- Size: Large
- Workstream: Style Inspiration, Creators & Profile
- Original Description: Store whether a Look was created by the user, with Muse, generated by Muse, recreated from inspiration, or created through another supported source.

## Problem

The current `0.html` prototype exposes this area through Canonical Look state used by F-01 Studio, M-02 Muse, K-04 creator, G-01/G-02 saved Looks. The relevant rendering/routing surface is `screens registry, renderScreen, go, studioScreen / mirrorStudioV2, museScreen / enrichCoreScreens, discoverScreen / mirrorDiscover, savedScreen`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-044.

## UX Decision

- Add canonical Look provenance/source metadata.
- Support at least Created by Me, With Muse, Muse Generated, Recreated from Inspiration, and any final approved states.
- Set the source at creation time from Studio, Muse, Lens, Creator Make It Mine, etc.
- Use this single field/model for Profile counts and filters.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`L-01/K-01/G-01 expose related content through separate destinations with limited shared attribution/state.`

## Target Flow

`Current context → Track Look creation source → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens

- Audit/change: Canonical Look state used by F-01 Studio, M-02 Muse, K-04 creator, G-01/G-02 saved Looks
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
- New standalone route: not assumed; first attempt to solve inside the mapped canonical surface.

## Technical Impact

- HTML/CSS/JS baseline: `0.html`
- Functions/routes: `screens registry, renderScreen, go, studioScreen / mirrorStudioV2, museScreen / enrichCoreScreens, discoverScreen / mirrorDiscover, savedScreen`
- Shared UI: `shell`, root/bottom navigation, reusable sheet/overlay patterns, image components, and accessibility labels.
- State: reuse the relevant canonical prototype state; do not fork Closet, Look, Canvas, Planner, Trip, Twin, Lens, or Muse data.
- Persistence: the baseline has no canonical localStorage model; add persistence only when this ticket explicitly requires it and test migration/reset behavior.
- Tests: add/extend dedicated Playwright coverage for `0.html` on desktop and 375×812 mobile.
