# SIQ-052 — Compress Style Twin setup

## Ticket

- ID: SIQ-052
- Comment: Compress Style Twin setup
- Scope: Specific Screen
- Screen / Product Area: Style Twin
- Size: Large
- Workstream: Style Twin
- Original Description: Reduce Style Twin setup to roughly 3–4 meaningful steps by combining guidance/upload and moving optional appearance controls later.

## Problem

The current `0.html` prototype exposes this area through H-01–H-10 compressed into 3–4 meaningful states. The relevant rendering/routing surface is `screens registry, renderScreen, go, avatarScreen / mirrorTwinIntro / mirrorUpload`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-052.

## UX Decision

- Reduce the current multi-screen setup to roughly 3–4 meaningful steps.
- Combine face guidance + upload and body reference + basic measurements where practical.
- Move pose, tuck, appearance, and usage details to optional controls after the first result.
- Keep save-and-resume/retry/privacy behavior.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`A-07/A-08 or H-01 → H-02–H-09 setup → H-10 result.`

## Target Flow

`Current context → Compress Style Twin setup → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
