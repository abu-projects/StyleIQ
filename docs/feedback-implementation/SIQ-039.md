# SIQ-039 — Make Style Inspiration easier to discover

## Ticket

- ID: SIQ-039
- Comment: Make Style Inspiration easier to discover
- Scope: Specific Screen
- Screen / Product Area: Style Inspiration
- Size: Medium
- Workstream: Style Inspiration, Creators & Profile
- Original Description: Surface the Style Inspiration area more clearly from Profile so users can understand where personal looks, screenshots, creators, Instagram, and Pinterest references are managed.

## Problem

The current `0.html` prototype exposes this area through L-01 Profile and K-01 inspiration/discovery. The relevant rendering/routing surface is `screens registry, renderScreen, go, profileScreen / mirrorProfile, discoverScreen / mirrorDiscover`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-039.

## UX Decision

- Add a clear Profile/My Atelier entry for Style Inspiration.
- Use descriptive copy indicating photos, screenshots, Instagram, Pinterest, creators, and celebrities.
- Do not create a second Style Inspiration data model; expose the canonical one.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`L-01/K-01/G-01 expose related content through separate destinations with limited shared attribution/state.`

## Target Flow

`Current context → Make Style Inspiration easier to discover → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

- Audit/change: L-01 Profile and K-01 inspiration/discovery
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
