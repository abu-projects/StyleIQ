# SIQ-009 — Lens: Recreate someone's outfit

## Ticket

- ID: SIQ-009
- Comment: Lens: Recreate someone's outfit
- Scope: General
- Screen / Product Area: StyleIQ Lens
- Size: Large
- Workstream: StyleIQ Lens & Visual Search
- Original Description: Point StyleIQ Lens at another person's outfit and translate the outfit formula into equivalent pieces from the user's Closet.

## Problem

The current `0.html` prototype exposes this area through Lens result → C-01 equivalents → F-01 simple Studio. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset, studioScreen / mirrorStudioV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-009.

## UX Decision

- Detect the outfit formula from a photographed person/outfit without identifying the person.
- Map visible garment roles to equivalent owned Closet pieces first.
- Show owned equivalents, missing roles, and a primary Make It Mine action.
- Allow the result to open in simple Studio editing only if the user wants to adjust it.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`Visual jobs are split between B import, C Closet, K Discover, M Muse, and J Trips; no canonical Lens route exists.`

## Target Flow

`Current context → Lens: Recreate someone's outfit → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
