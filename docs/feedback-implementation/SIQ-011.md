# SIQ-011 — Lens: Check my suitcase

## Ticket

- ID: SIQ-011
- Comment: Lens: Check my suitcase
- Scope: General
- Screen / Product Area: StyleIQ Lens
- Size: Medium
- Workstream: StyleIQ Lens & Visual Search
- Original Description: Allow StyleIQ Lens to review a suitcase or packed items and identify useful missing items for the trip.

## Problem

The current `0.html` prototype exposes this area through Lens result → J-08 packing review / J-14 Trip hub. The relevant rendering/routing surface is `screens registry, renderScreen, go, tripScreenV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-011.

## UX Decision

- From suitcase/packing input, recognize visible packed categories/items where possible.
- Compare against current Trip context when available.
- Surface likely missing essentials or redundancies as suggestions, not mandatory corrections.
- Allow one-tap handoff into the Trip packing list.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`Visual jobs are split between B import, C Closet, K Discover, M Muse, and J Trips; no canonical Lens route exists.`

## Target Flow

`Current context → Lens: Check my suitcase → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
