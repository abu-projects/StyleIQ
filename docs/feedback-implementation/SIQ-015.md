# SIQ-015 — Simplify Man / Woman styling selection

## Ticket

- ID: SIQ-015
- Comment: Simplify Man / Woman styling selection
- Scope: Specific Screen
- Screen / Product Area: Onboarding
- Size: Medium
- Workstream: Onboarding
- Original Description: Keep styling context simple and wardrobe-focused, such as Womenswear, Menswear, or Both, without turning it into a demographic questionnaire.

## Problem

The current `0.html` prototype exposes this area through S-02 Who are we styling?, A-06 Wardrobe preference, L-04 About you. The relevant rendering/routing surface is `screens registry, renderScreen, go, onboarding, profileScreen / mirrorProfile`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-015.

## UX Decision

- Treat this as wardrobe styling context, not identity collection.
- Use concise options such as Womenswear, Menswear, and Both only if required by product behavior.
- Do not duplicate the same choice in onboarding and Profile.
- Keep the chosen context editable later.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`S-00 → S-01 → S-02 → A-series setup screens → A-11/D-02 first value.`

## Target Flow

`Current context → Simplify Man / Woman styling selection → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
