# SIQ-026 — Use chips for lightweight choices

## Ticket

- ID: SIQ-026
- Comment: Use chips for lightweight choices
- Scope: General
- Screen / Product Area: Whole Product
- Size: Medium
- Workstream: Product Simplification Foundation
- Original Description: Replace unnecessary setup pages with contextual chips for occasions, preferences, travel context, dress codes, and other small selections.

## Problem

The current `0.html` prototype exposes this area through D-04 outfit families, I-03/I-04 event context, J-01/J-02 trip context, F-01 Studio. The relevant rendering/routing surface is `screens registry, renderScreen, go, homeScreen / mirrorToday / outfitFamilies, plannerScreen / mirrorPlanner, tripScreenV2, studioScreen / mirrorStudioV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-026.

## UX Decision

- Use chips for compact, low-risk selections such as occasion, dress code, trip context, preference, and filters.
- Avoid creating a full screen for a choice that can be expressed in a few chips.
- Keep chip states readable, accessible, and reversible.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`The screen index exposes the capability through feature-specific routes, often with separate full-screen configuration, processing, and result states.`

## Target Flow

`Current context → Use chips for lightweight choices → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
