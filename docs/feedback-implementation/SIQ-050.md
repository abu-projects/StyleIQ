# SIQ-050 — Hide technical editor terminology

## Ticket

- ID: SIQ-050
- Comment: Hide technical editor terminology
- Scope: Specific Screen
- Screen / Product Area: Style Studio
- Size: Small
- Workstream: Style Studio
- Original Description: Do not expose implementation terms such as Category Layer, Manual Selector, Multi-select Layers, or Provenance in the standard user experience.

## Problem

The current `0.html` prototype exposes this area through F-05, F-07, F-08, F-09 labels and accessibility copy. The relevant rendering/routing surface is `screens registry, renderScreen, go, studioScreen / mirrorStudioV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-050.

## UX Decision

- Replace user-facing terms such as Category Layer, Manual Selector, Multi-select Layers, Provenance with natural wardrobe/action language.
- Keep technical terminology internal to code/docs if useful.
- Review all Studio labels, helper copy, and accessibility labels.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`F-01 → technical layer/category/manual-selection screens → save.`

## Target Flow

`Current context → Hide technical editor terminology → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
