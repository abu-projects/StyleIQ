- Original Description: Use one-tap approval when item detection is confident. Ask the user for clarification only when important attributes are uncertain or conflicting.

## Problem

The current `0.html` prototype exposes this area through B-06 confirmation, B-10 unresolved drafts, shared Lens/import review. The relevant rendering/routing surface is `screens registry, renderScreen, go, importScreen / mirrorItemUpload`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-036.

## UX Decision

- Define prototype confidence outcomes: high confidence, uncertain field, failed/ambiguous.
- High confidence should use one-tap Looks Right / Edit or automatic add where appropriate.
- Only uncertain critical attributes should trigger clarification.
- Group multiple uncertain fields into one review surface.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.
