# SIQ-041 — Center creator experience around Make It Mine

## Ticket

- ID: SIQ-041
- Comment: Center creator experience around Make It Mine
- Scope: Specific Screen
- Screen / Product Area: Discover / Creators
- Size: Large
- Workstream: Style Inspiration, Creators & Profile
- Original Description: Translate creator inspiration into the user's own wardrobe and show how many equivalent pieces they already own instead of focusing primarily on social following.

## Problem

The current `0.html` prototype exposes this area through K-04 creator Look detail, K-06 Restyle, F-01 Studio. The relevant rendering/routing surface is `screens registry, renderScreen, go, discoverScreen / mirrorDiscover, studioScreen / mirrorStudioV2`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-041.

## UX Decision

- Make the primary creator value proposition translating inspiration into the user's own Closet.
- Show how many equivalent roles/items the user already owns.
- Use one Make It Mine action to build an editable look with Closet equivalents.
- Keep creator profile/social exploration secondary.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`L-01/K-01/G-01 expose related content through separate destinations with limited shared attribution/state.`

## Target Flow

`Current context → Center creator experience around Make It Mine → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens

- Audit/change: K-04 creator Look detail, K-06 Restyle, F-01 Studio
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
- New standalone route: not assumed; first attempt to solve inside the mapped canonical surface.
