# SIQ-055 — Generate plans from natural language

## Ticket

- ID: SIQ-055
- Comment: Generate plans from natural language
- Scope: Specific Screen
- Screen / Product Area: Planner
- Size: Large
- Workstream: Planner
- Original Description: Support inputs such as “Client presentation at 10, drinks after work” and let StyleIQ create the underlying plan and suggested outfit automatically.

## Problem

The current `0.html` prototype exposes this area through I-03/I-04 natural-language composer feeding Planner and D-04 Look generation. The relevant rendering/routing surface is `screens registry, renderScreen, go, plannerScreen / mirrorPlanner, homeScreen / mirrorToday / outfitFamilies`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-055.

## UX Decision

- Support realistic sentences such as 'Client presentation at 10, drinks after work.'
- Translate the sentence into internal planning context and a styling request.
- Show the interpreted context briefly and let the user correct it if needed.
- Then generate or select a Look without a long form.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`I-01 → I-03 → I-04 form → I-05 validation → generated Look.`

## Target Flow

`Current context → Generate plans from natural language → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
