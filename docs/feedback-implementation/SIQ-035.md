# SIQ-035 — Let AI handle item processing automatically

## Ticket

- ID: SIQ-035
- Comment: Let AI handle item processing automatically
- Scope: Specific Screen
- Screen / Product Area: Closet Import
- Size: Large
- Workstream: Closet & Photo Import
- Original Description: After a photo is provided, automatically crop, isolate the garment, normalize the image, classify it, infer metadata, and add it with minimal user intervention.

## Problem

The current `0.html` prototype exposes this area through B-02, B-03, B-06–B-08, B-11. The relevant rendering/routing surface is `screens registry, renderScreen, go, importScreen / mirrorItemUpload`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-035.

## UX Decision

- After photo/link input, run cleanup, classification, and metadata inference as background behavior.
- Do not expose internal AI stages as separate mandatory screens.
- Add high-confidence items directly or through one compact approval state.
- Retain transparent recovery for failed processing.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`B-01 → B-02 → B-03 → B-06 → B-07 → B-08 → B-11 → C-01.`

## Target Flow

`Current context → Let AI handle item processing automatically → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
