## Ticket

- Size: Large
- Workstream: Outfit Actions & Saved Looks
- Original Description: Keep the outfit image and primary actions on one page. Move items and additional details into expandable sections and visibility/delete into an overflow menu.

## Problem

The current `0.html` prototype exposes this area through G-02–G-08 consolidated around G-02. The relevant rendering/routing surface is `screens registry, renderScreen, go, savedScreen`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-047.

## UX Decision

- Consolidate items, classification, value, visibility, social metrics, and delete behavior around one Look detail page.
- Primary actions should be Wear, Try On, Edit, Plan.
- Use expandable Items and About This Look sections.
- Move visibility/delete to overflow; show social metrics only when contextually relevant.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`D-04/G-02 → separate E/G subroutes for save, feedback, sharing, metadata, visibility, and delete.`

## Target Flow

`Current context → Simplify Saved Look details → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
