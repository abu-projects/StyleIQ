# SIQ-030 — Make the Closet an actual visual wardrobe

## Ticket

- ID: SIQ-030
- Comment: Make the Closet an actual visual wardrobe
- Scope: Specific Screen
- Screen / Product Area: Closet
- Size: Large
- Workstream: Closet & Photo Import
- Original Description: The primary Closet experience should prominently display owned items and categories rather than behaving mainly as a readiness or analytics dashboard.

## Problem

The current `0.html` prototype exposes this area through C-01 Closet. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-030.

## UX Decision

- Make owned garments the primary content of Closet.
- Reduce readiness/analytics dominance on the root Closet page.
- Keep insights secondary and contextual.
- Preserve quick Add/Lens access and direct category browsing.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`C-01 → C-02 → separate C-03/C-04/C-05/C-06/C-07 screens.`

## Target Flow

`Current context → Make the Closet an actual visual wardrobe → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

- Audit/change: C-01 Closet
- Retain until replacement passes: all existing entry, back, cancel, empty, and error paths around those screens.
- Remove/merge only after the replacement journey is verified.
