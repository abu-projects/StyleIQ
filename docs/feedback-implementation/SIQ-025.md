# SIQ-025 — Use progressive disclosure

## Ticket

- ID: SIQ-025
- Comment: Use progressive disclosure
- Scope: General
- Screen / Product Area: Whole Product
- Size: Foundation
- Workstream: Product Simplification Foundation
- Original Description: Show images, recommendations, and primary actions first. Reveal detailed metadata, settings, and advanced controls only when requested.

## Problem

The current `0.html` prototype exposes this area through C-02 Item detail, G-02 Saved Look, H-01 Twin, F-01 Studio, I-01 Planner, L-01 Profile. The relevant rendering/routing surface is `screens registry, renderScreen, go, closetScreen / mirrorCloset, savedScreen, avatarScreen / mirrorTwinIntro / mirrorUpload, studioScreen / mirrorStudioV2, plannerScreen / mirrorPlanner, profileScreen / mirrorProfile`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-025.

## UX Decision

- Show the visual result, primary action, and essential context first.
- Place metadata, stats, settings, classifications, and advanced controls in expandable sections, sheets, or overflow menus.
- Apply the rule consistently to Item Detail, Saved Look, Style Twin, Studio, Planner, and Profile.
- Do not hide information needed for an immediate decision.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`The screen index exposes the capability through feature-specific routes, often with separate full-screen configuration, processing, and result states.`

## Target Flow

`Current context → Use progressive disclosure → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.

## Affected Screens

- Audit/change: C-02 Item detail, G-02 Saved Look, H-01 Twin, F-01 Studio, I-01 Planner, L-01 Profile

- Remove/merge only after the replacement journey is verified.
