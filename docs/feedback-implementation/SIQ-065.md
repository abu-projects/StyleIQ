# SIQ-065 — Use one-tap approval when confidence is high

## Ticket

- ID: SIQ-065
- Comment: Use one-tap approval when confidence is high
- Scope: General
- Screen / Product Area: AI Interaction
- Size: Medium
- Workstream: Closet & Photo Import
- Original Description: When StyleIQ confidently understands an item, context, or recommendation, offer a simple Looks Right / Edit pattern rather than forcing a full confirmation form.

## Problem

The current `0.html` prototype exposes this area through B-06 and shared AI review surfaces in Lens/Planner/Trips. The relevant rendering/routing surface is `screens registry, renderScreen, go, importScreen / mirrorItemUpload`.

Current behavior is partially represented, but the ticket acceptance is not proven end to end. The existing architecture still exposes feature-oriented routes and, where applicable, separate configuration, processing, or result states. No dedicated `0.html` regression evidence currently closes SIQ-065.

## UX Decision

- Introduce a reusable approval pattern such as Looks Right / Edit.
- Apply it to item detection, photo learning, Lens extraction, and interpreted context when confidence is high.
- Do not show long forms by default.
- Keep the user able to inspect/edit inferred data.

The decision must preserve the existing editorial/liquid-material direction, reduce decisions and nested screens, and reuse canonical state rather than creating a parallel feature.

## Current Flow

`The screen index exposes the capability through feature-specific routes, often with separate full-screen configuration, processing, and result states.`

## Target Flow

`Current context → Use one-tap approval when confidence is high → immediate useful result or primary action → optional edit/sheet only when needed.`

Use a full screen only for a distinct user job. Prefer direct action, inline state, one shared bottom sheet, background work, or progressive disclosure for intermediate steps.
